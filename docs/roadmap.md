## 五、依赖与建议顺序

**几条硬依赖：**

- `E1 乐句统计` → `E2 乐句级效果接线`。没有乐句标记，那批效果永远接不上，而它们正是"技能不赚钱"这个结构问题的解药。
- `P4 可授权音频` → `R4 完整发布包`。音频没换，包不能发。
- `D4 难度曲线` → `P1 曲库` 的选取方式。先定分层规则，再决定曲库怎么搭。
- `D1 构筑` → 整个"难度上升 / 构筑抵消"的闭环。这是设计上最大的一块空。

**建议顺序（供参考）：**

1. **补完整一局的闭环**：终房遭遇曲目（D7）+ 歌曲进掉落表（E5），让三条获取渠道都通。这一步不改架构，只加配表，却能立刻让"一局旅程"完整。
2. **做一首可以公开的曲子**：换一首可授权音频（P4），手工打一张完整谱（P3），从进游戏到结算跑通。这一步之后你就有了**可以给人看的东西**，而不是只有框架。
3. **解乐句依赖**：在谱面里加乐句标记（E1），然后接线乐句级效果（E2）。这一步会直接改变数值模拟的结论。
4. **构筑排期**：D1 单独当作一个大工程来做，不要夹在别的任务里。
5. 其余工程项与发布前事项，随进度收尾。
