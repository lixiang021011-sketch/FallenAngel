# FallenAngel 架构约定

> 本文档是**开发规范**：所有新增/修改代码必须遵守。与现状代码不一致的地方，以"改造点"标注。
> 游戏设计见 [项目说明.md](项目说明.md)。

## 1. 分层架构

`Assets/Scripts/` 下按职责分六层，命名空间与目录一一对应：

| 层 | 命名空间 | 职责 | 现有主要类 |
| --- | --- | --- | --- |
| Core | `FallenAngel.Core` | 全局状态、判定规则、共享布局约定、场景构建工具 | GameManager、JudgeDefine、LaneLayout、CalibrationSettings、Loc、SceneBuilder、Compat |
| Data | `FallenAngel.Data` | 数据结构与加载（纯数据，无行为依赖） | ChartData、NoteData、ChartLoader |
| Gameplay | `FallenAngel.Gameplay` | 音符生成/下落/判定/计分 | NoteSpawner、Note、JudgeManager、NotePrefabBuilder |
| Input | `FallenAngel.InputSystem` | 输入采集与抽象 | InputManager |
| UI | `FallenAngel.UI` | 界面显示与交互 | GameStarter、HUDController、ResultScreen、PauseController、LaneKeyVisual、CalibrationController、LanguagePanelController、HitFeedbackController、RippleGraphic、LocalizedText |
| Audio | `FallenAngel.Audio` | 音频播放与时间同步 | AudioManager、SynthesizedSfx |

**依赖规则**：
- 只允许向 Core / Data 依赖；Gameplay、Input、UI、Audio 之间**不得相互直接调用方法**，只能通过事件或 Core 中转。
- Data 是纯数据层，不引用 UnityEngine 行为类（MonoBehaviour）以外的任何运行时模块。
- UI 只做"读状态 + 显示 + 转发用户操作"，禁止在 UI 层写玩法逻辑。

## 2. 单例约定

采用"懒初始化判重"模式（现状代码的统一写法）：

```csharp
private void Awake()
{
    if (Instance != null && Instance != this)
    {
        Destroy(gameObject);
        return;
    }
    Instance = this;
}
private void OnDestroy()
{
    if (Instance == this) Instance = null;
}
```

- **已登记单例**：GameManager（唯一 `DontDestroyOnLoad`）、JudgeManager、NoteSpawner、InputManager、AudioManager。
- 新增单例必须在本文档登记；除 GameManager 外**不要** `DontDestroyOnLoad`（场景由 SceneBuilder 重建，单例随场景销毁重建）。
- 跨模块状态修改一律走公开方法（如 `GameManager.LoadChart`），禁止直接改别人的 `[SerializeField]` 字段。

## 3. 事件通信约定

通信采用 **C# 事件**（`System.Action` 委托或 `event EventHandler<TArgs>`），不使用任何第三方消息框架。

- **事件命名**：`OnXxx`；参数多于 1 个时定义专用 `struct`/`class`（参考 `LaneInputArgs`）。
- **订阅位置规范**（现状统一模式，新代码照抄）：
  ```csharp
  private void OnEnable()  { Subscribe(); }      // 订阅
  private void Start()     { Subscribe(); }      // 先退订再订阅，防 Awake 顺序导致漏订/重订
  private void OnDisable() { Unsubscribe(); }    // 退订
  ```
  `Subscribe` 内部必须先 `-=` 再 `+=`。
- **已登记事件**：
  - `GameManager`：`OnStateChanged(GameState)`、`OnGameStart`、`OnGameEnd`
  - `JudgeManager`：`OnJudgeResult(JudgeResultType, int lane)`、`OnJudgeBias(float)`（判定偏差，正=早，HUD 早/晚指示用）、`OnComboUpdate(int, bool)`、`OnScoreUpdate(int)`、`OnJudgeCountsUpdate(int×5)`
  - `InputManager`：`OnLaneInput(object, LaneInputArgs)`
  - `Loc`（静态类）：`OnLanguageChanged`（语言切换，LocalizedText 订阅刷新）
- **禁止**：在 `Update` 中订阅/退订；订阅者反向修改发布者私有状态；用轮询（每帧查状态）替代事件。

## 4. 核心数据流

### 4.1 谱面加载 → 开局
```
GameStarter(选曲/按钮) → ChartLoader(Resources/JSON 解析) → GameManager.LoadChart
  → 状态 Loading → GameStarter 收到 OnStateChanged(Loading) → StartCountdownAndPlay
  → 3-2-1-GO → 状态 Playing → OnGameStart 广播 → NoteSpawner 清场重置 / JudgeManager 重置统计
```

### 4.2 音符生命周期
```
NoteSpawner.Update 按 SongTime+fallTime 扫描谱面 → 对象池 Get → Note.Initialize
  → Note.UpdatePosition 每帧下落 → 判定（命中/自动Miss）→ 特效协程 → 回收到池
```
- 音符的创建与销毁**只允许**经 `NoteSpawner` 的对象池（`UnityEngine.Pool`），禁止直接 `Instantiate`/`Destroy` 音符。
- `Compat.SimpleObjectPool` 仅为低版本兜底，2022.3 不会走到，**新代码不要使用它**。

### 4.3 判定流
```
InputManager.OnLaneInput → JudgeManager.HandleLaneInput（校验 Playing 状态）
  → NoteSpawner.GetClosestJudgableNote(lane) → JudgeWindows.Judge(时差)
  → 计分/连击/计数 → OnJudgeResult/OnScoreUpdate/OnComboUpdate/OnJudgeCountsUpdate → HUD
  → AudioManager.PlayHitSfx
```

### 4.4 结果流
```
GameManager.Update 检测 SongTime ≥ 谱面总时长 → EndGame → 状态 Result
  → OnGameEnd → ResultScreen.ShowResult（读 JudgeManager 统计）
```

## 5. 计时与音画同步约定

- **唯一权威时间源：`GameManager.SongTime`**。任何需要歌曲时间的代码（判定、生成、进度条）一律读取它，**禁止自建计时器**。
- 供时方是 `AudioManager`（唯一时钟，2026-08-13 起）：真实音频在播时以 `bgmSource.time` 为准；无音频时内部虚拟钟（unscaledTime）兜底。`GameManager.Update` 每帧读取 `AudioManager.CurrentTime` 并统一扣除 `metadata.offset`，**AudioManager 不写 SongTime**。
- BGM 播放时机：`AudioManager.LoadBGM` 只装载不播放；`OnGameStart`（倒计时结束的 GO 时刻）统一触发播放，保证开局时间从 0 与音乐对齐。
- 曲终检测：真实音频播完（`HasAudioFinished`）或 `SongTime >= GetTotalDuration()`（虚拟钟兜底）。
- 曲终淡出：`EndGame` 调用 `AudioManager.FadeOutBGM()`（时长 `endFadeOutDuration`，unscaledDeltaTime 驱动）；`StopAll` 会中断淡出并复位音量，重试/返回菜单路径安全。
- 暂停机制：`Time.timeScale = 0` + `bgmSource.Pause()`；虚拟钟由状态门控自动冻结；时间连续性由单一时钟自然保证，无需补偿代码。
- `offset` 校准为单行道：只在"读时钟时扣一次"，BGM 永远从头播。校准 = 改 `metadata.offset` 一处。

## 6. UI 层级约定

场景 UI 由 `SceneBuilder` 按固定层级与命名生成，`PauseController`/`ResultScreen` 的 `FindReferences` **依赖这些命名**。修改层级必须同步修改查找逻辑：

```
Canvas
├─ MenuPanel                        [GameStarter 挂载处]
├─ GamePanel                        [ResultScreen 挂载处（始终激活）]
│  ├─ HUDPanel                      [PauseController 挂载处（始终激活）]
│  │  ├─ ScoreText / ComboText / ComboLabel / JudgeText / JudgeBiasText（早/晚指示）/ SongTitle
│  │  ├─ ProgressBarBG / ProgressFill / ProgressText / PauseButton
│  ├─ CountdownText
│  ├─ PausePanel ─ PauseRoot        [ResumeButton / RetryButton / ExitButton]
│  ├─ ResultPanel ─ ResultRoot      [SongName / Artist / Difficulty / Rank / Score /
│  │                                  Accuracy / MaxCombo / Label_*/Val_* / RetryButton / BackButton]
│  └─ LanesBG
│     ├─ Lane0~3_BG
│     ├─ JudgeLine
│     ├─ NotesContainer             [NoteSpawner 挂载处]
│     └─ KeyArea ─ Lane0~3_Key      [LaneKeyVisual 挂载处，含 KeyIcon / JudgeGlow]
├─ HitFeedbackLayer                 [HitFeedbackController 挂载处，触点涟漪层，盖在游戏层之上菜单层之下]
├─ CalibrationPanel                 [CalibrationController 挂载处，含菜单入口按钮 CalibrationButton]
├─ LanguagePanel                    [LanguagePanelController 挂载处，语言按钮遍历 Language 枚举生成，当前语言置灰]
```

- 面板显隐由 `GameStarter.OnGameStateChanged`、`PauseController`、`ResultScreen` 分工负责，新增面板必须走同一状态机路径。
- **轨道布局统一取自 `Core/LaneLayout`**（Canvas 本地坐标）：SceneBuilder 视觉、NoteSpawner 音符、InputManager 输入判定三者同源。**输入判定必须先将屏幕坐标转换为 Canvas 本地坐标再判轨道**（`InputManager.GetLaneFromScreenPos`），禁止按屏幕比例直接划分——不同视图下 CanvasScaler 的缩放/裁切会导致按键错位。
- 占位美术（纯色 Image）仅用于功能验证，正式美术替换时保持节点名与挂载不变。

## 7. 代码规范

- **命名空间**：`FallenAngel.{层名}`，禁止全局命名空间。
- **命名**：PascalCase（类/方法/属性/事件）、camelCase（私有字段）、布尔用 `is`/`has` 前缀。
- **序列化字段**：`[SerializeField] private` + `[Header]`/`[Tooltip]` 中文说明，绝不 public 字段裸奔。
- **状态暴露**：`public T Xxx { get; private set; }`，外部修改走方法。
- **注释**：类/公共成员用中文 XML 注释（`/// <summary>`）；复杂逻辑行内注释说明"为什么"。
- **日志**：`Debug.Log("[类名] 内容")` 前缀；错误用 LogError，可恢复异常用 LogWarning。
- **协程与缩放时间**：UI 动画用 `Time.unscaledDeltaTime`（暂停时也要动）；玩法逻辑用 `SongTime`（见 §5）。

## 8. 资源与数据约定

- 动态加载走 `Resources/`：谱面 `Resources/Charts/*.json.bytes`（JsonUtility，字段 public）、音频 `Resources/Audio/`。
- **多语言**：玩家可见文本一律走 `Loc.T(key)`，禁止硬编码。语言文件 `Resources/Localization/{zh-CN,en-US}.json`（entries 列表结构，JsonUtility 兼容）；静态文本由 SceneBuilder 挂 `LocalizedText`（key=语言表 key），动态文本（分数/进度等运行时赋值）以字面量作 key 不在表中，`Loc.HasKey=false` 保证语言切换不覆盖运行时内容。新增语言步骤：`Language` 枚举加值 → 加语言表 → 如需专用字体在 SceneBuilder 字体映射处扩展（当前统一 CJK 字体，思源黑体可覆盖中/日/韩/拉丁）。
- 谱面字段定义以 `ChartData`/`NoteData` 为准，修改结构时同步更新 [项目说明.md](项目说明.md) §5.1 的格式文档。
- `.meta` 文件全部入库；重命名/移动资产只在 Unity 编辑器内进行。
- 预制体目前仅 `Assets/Prefabs/Note.prefab`（由菜单生成）。

## 9. Roguelike 扩展预留（阶段三，实现前先评审本节）

**核心原则**：buff/debuff **不得直接修改**核心系统的序列化字段（如 `JudgeManager.judgeWindows`、`GameManager.noteFallTime`）。采用"**基础值 + 修改器**"模式：核心系统提供"有效值"属性，效果系统通过一个集中组件施加修改。

拟定结构（实现时落地）：

```
Roguelike
├─ ModifierManager（单例，登记）
│   职责：buff/debuff 列表、叠加规则、时长倒计时、OnModifierApplied/OnModifierExpired 事件
├─ 效果基类 ModifierEffect：Apply(Rules)/Tick/Expire 生命周期
└─ Rules（只读聚合）：向核心系统提供"有效参数"
     EffectiveJudgeWindows、EffectiveFallTime、JudgeLineVisible、NotesVisible、…
```

- **首批效果与接入点约定**：
  | 效果 | 实现方式 |
  | --- | --- |
  | 判定变松/变严格 | `Rules.EffectiveJudgeWindows` 按倍率缩放；JudgeManager 判定时读它（改造点：现读序列化字段） |
  | 判定线消失 | `Rules.JudgeLineVisible`；LaneKeyVisual/JudgeLine 渲染层读它（判定逻辑不受影响） |
  | 谱面短暂隐身 | `Rules.NotesVisible`；Note.UpdatePosition 渲染时读它（位置/判定照常） |
  | 一键清屏 | `NoteSpawner` 提供公开接口 `ClearAllActiveNotes()`（现有私有 `ClearAllNotes` 改造暴露），效果调用接口，**禁止**直接操作 `activeNotes` |
- **音画同步在 roguelike 下的约束**：所有时长类效果用 `GameManager.SongTime` 计时（§5），暂停时效果计时冻结（与游戏一致）。
- **现有关卡改造点预告**：`JudgeManager.judgeWindows`（判定时读）、`NoteSpawner.missThreshold` 缓存字段（自动 Miss 阈值）、判定线/音符可见性均需改为经 Rules 读取；改造前先更新本文档。
