# 谱面转换协议 v1（Notation → FallenAngel Chart）

> 数字乐谱格式（mscz / MusicXML / MIDI / gp / .chart）→ FallenAngel 谱面 JSON 的转换规则手册。
> 本文是唯一语义权威：转换器实现必须对照本文，分歧时以本文为准（本文滞后时先改本文）。
> 2026-08-18 定稿音符规格（5 类 + 事件通道），IR/规则引擎骨架待实现。

## 0. 架构：两段式管线

```
mscz / MusicXML / MIDI / gp / .chart
        │  ① 前端解析器（每种源格式一个；只负责格式怪癖 → 归一化 IR）
        ▼
  归一化 IR：音乐事件流 {tick, time, pitch, duration, velocity, instrument, articulations}
        │  ② 规则引擎（唯一一个；读 JSON 声明式规则）
        ▼
  FallenAngel Chart v2 JSON（5 类音符 + 事件通道）
```

**设计原则**
1. **复杂度隔离**：格式解析与谱面映射解耦。新增源格式 = 只写前端；调整映射偏好 = 只改规则 JSON，不碰代码。
2. **规则是数据不是代码**：规则文件可读可改可 diff，谱面作者可直接参与调规则。
3. **IR→chart 是纯函数**：可单元测试、可回归、可往返验证（沿用 chart↔MusicXML 零差异往返的方法论）。
4. **单向生成，不保证逆转换**：chart→乐谱是信息损失操作，不做承诺；但 IR→chart 必须确定性（同输入同输出）。

## 1. 目标格式：FallenAngel Chart v2

### 1.1 音符类型（5 类，定稿）

| type | 判定语义 | 必填字段 | 可选字段 |
|---|---|---|---|
| `tap` | 标准时间窗口 | `time`, `lane` | — |
| `hold` | 定轨长按（头+身+尾） | `time`, `lane`, `duration` | — |
| `drag` | **Phigros 语义：碰即 Perfect，永不 MISS** | `time`, `lane` | `duration` |
| `flick` | 时间窗口 + **方向判定** | `time`, `lane`, `direction` | — |
| `slide` | 长按 + **轨道间无间断平滑横移** | `time`, `duration`, `path` | `lane`（起始轨，可由 path[0].x 推出） |

**字段语义**
- `lane`：整数 0-4（5 键），轨道颜色按游戏侧 LaneColors 定义。`flick` 的 `direction` 取值 `"up" | "down"`（字符串枚举，增量可扩展）。
- `slide.path`：路径点数组 `[{"t": 偏移秒, "x": 连续轨道坐标}]`。
  - `t` 相对 slide 起点，首点必须 `t=0`，末点 `t=duration`，单调递增。
  - `x` 连续坐标 0.0~4.0：整数 = 轨道中心，小数 = 两轨之间。
  - 点间线性插值（未来版本可加贝塞尔，path 点加 `curve` 字段即可，不破坏现有）。
- `hold` 沿用现有 LongStart/LongEnd 生成约定：转换器输出时写 hold，游戏加载侧拆头/身/尾。

**示例**
```json
{
  "type": "flick", "time": 60.0, "lane": 2, "direction": "up"
}
{
  "type": "slide", "time": 75.0, "duration": 2.0,
  "path": [{"t": 0.0, "x": 1.0}, {"t": 0.8, "x": 2.5}, {"t": 2.0, "x": 4.0}]
}
```

### 1.2 事件通道（非音符）

```json
"events": [
  {"time": 0.0, "type": "bpm",   "value": 160.026},
  {"time": 30.0, "type": "speed", "value": 2.0}
]
```
- v1 支持 `bpm`（变速）与 `speed`（下落速度倍率）。
- 通道是未来 Phigros 式判定线移动/演出事件的预留位：新事件只加 `type`，不破坏格式。

### 1.3 metadata

现有字段（songName/songArtist/chartAuthor/difficulty/level/bpm/offset/audioFileName/preview*）外加：
- `formatVersion: 2`（v1 旧谱面 = 1，加载侧据此兼容）
- `noteCounts`：各类型数量统计（校验用）

## 2. 归一化 IR（中间表示）

### 2.1 事件模型

```json
{
  "tick": 15360,                 // IR 标准 tick（绝对位置，PPQ=768；前端必须归一化到此分辨率）
  "time": 60.0,                  // 绝对秒（所有格式统一换算到此，BPM 变化已折算）
  "pitch": 46,                   // MIDI 音高；鼓 = GM 鼓件号；无音高（打击噪声类）填 null
  "duration": 0.5,               // 秒（tap 类可为 0）
  "duration_ticks": 1536,        // 时值（IR 刻度，tie 链合并后求和）——拍数判定专用
  "velocity": 0.8,               // 0-1（无力度信息的格式填 0.5 中性值）
  "instrument": "drums",         // 乐器类别：drums/bass/guitar/keys/vocals/other
  "staff": 0,                    // 声部/轨道序号（多轨谱）
  "articulations": ["grace"],    // 见 2.2 记号表
  "pitch_end": null,             // 参照音高：gliss 终点 / bend 目标 / grace 被装饰主音（方向判定用）
  "tied": false,                 // 是否 tie 链合并事件（合并必须在前端完成）
  "position": null               // 可选：源谱位置/技法数值，如 {"bend_semitones": 2, "strum_pitches": [40,45,52,57]}
}
```

**IR 实现约定（2026-08-18 骨架定稿）**
- **tick 一律归一化到 PPQ=768**（每四分音符 768 tick，沿用 mscz 前端惯例）。引擎按 `tick/768` 做拍数判定（hold 阈值、密集度），**与 BPM 无关**；无 tick 概念的格式填 0 仅用 time。前端负责把源分辨率换算到 768。
- `duration_ticks` 由前端按源时值 + tuplet 换算并归一化；tie 链合并后求和。
- `position` 承载有数值的技法细节：`bend_semitones`（推弦半音数）、`strum_pitches`（扫弦音高序列，低→高）。
- `pitch_end` 语义按记号分：gliss = 滑音终点；bend = 目标音高；grace = **被装饰的主音音高**（方向 = pitch_end 相对 pitch 的上下）。

### 2.2 演奏记号 → articulations 表（前端解析职责）

| 源记号 | articulation | 说明 |
|---|---|---|
| 延音线（同音高 tie 链） | `tie`（链合并为单事件，duration 求和） | 合并必须在**前端**完成，规则引擎只见合并后事件 |
| 连音线/滑音（变音高 slur/glissando） | `gliss`（带 `pitch_end`） | → Slide 来源 |
| 装饰音 grace note（鼓 flam） | `grace`（`pitch_end` = 被装饰主音） | → Flick 来源，主音时间上生成，方向 = pitch_end 相对上下 |
| 推弦/放弦 | `bend`/`release`（`position.bend_semitones` = 半音数） | → Slide 来源（位移 = 半音 × 0.5 轨） |
| 扫弦 | `strum`（**前端合并为单事件**，`position.strum_pitches` 低→高） | → 快速跨轨 drag 序列 |
| 震音 tremolo / 鼓滚奏 | `tremolo` | → Drag 来源 |
| 幽灵音（贝斯哑音） | `ghost` | → Drag（密集）/ Flick down（稀疏） |
| 击弦/勾弦 | `hammer_on`/`pull_off` | → Flick up / Drag（贝斯勾弦 → Drag） |
| slap | `slap` | → Flick down |
| 重音/断奏等 | `accent`/`staccato`/... | 目前不参与类型映射，保留供未来修饰 |

### 2.3 鼓件 pitch 对照表（GM，各前端统一）

| 鼓件 | pitch | 类别 |
|---|---|---|
| 底鼓 | 35, 36 | kick |
| 军鼓 | 37, 38, 40 | snare |
| 嗵鼓 | 41, 43, 45, 47, 48, 50 | tom |
| 闭镲 | 42 | hihat_closed |
| **踏板/部分闭镲** | 44 | hihat_pedal |
| **开镲** | 46 | hihat_open |
| 吊镲/叮叮 | 49, 51, 52, 55, 57, 59 | crash/ride |

### 2.4 前端职责清单（每格式一节，实现时按此对照）

**mscz / MusicXML（同一前端）**
- 鼓件：`<pitch>` = GM 鼓件号（MuseScore 鼓组映射已处理）；`<head>` 类型（x/circle）仅作参考
- 时值：durationType + dots 精确换算；Tuplet 栈式缩放；**多小节休止必须展开**（历史坑：m100 后整体提前）
- `<forward>`/`backup` 是 measure 级元素，空槽必须 forward 跳过（历史坑：音符被挤到小节开头）
- grace note：MusicXML 的 `<grace>` 标记 → `grace`；glissando 线 `<glissando>` → `gliss`
- tie 链合并：tie start/continue/stop 串成单事件

**MIDI**
- GM 通道 10 = 鼓件（pitch 即鼓件号）；其余通道按 Program 归类乐器
- note on/off 配对 → 事件；同 pitch 重叠音：取最早关闭者配对
- 无记号概念：tremolo/gliss 不可得，规则引擎按"乐器+时长+密集度"启发式可选启用

**gp（Guitar Pro）**
- fret/string → pitch；slide/legato slide 记号 → `gliss`；tremolo picking → `tremolo`；let-ring → hold 参考
- 多声部（voice）→ staff

**.chart（Moonscraper）**
- 已属于谱面域：前端直接产出 IR 全字段（含人工记号如 star power 可映射为事件）

## 3. 规则引擎

### 3.1 规则文件 JSON 语法

```json
{
  "version": 1,
  "lanes": 5,
  "rules": [
    {
      "name": "hihat-open-to-flick-up",
      "match": {"instrument": "drums", "pitch": 46},
      "emit": {"type": "flick", "lane": 2, "direction": "up"}
    },
    {
      "name": "hihat-pedal-to-flick-down",
      "match": {"instrument": "drums", "pitch": 44},
      "emit": {"type": "flick", "lane": 2, "direction": "down"}
    },
    {
      "name": "tremolo-to-drag",
      "match": {"articulations": ["tremolo"]},
      "emit": {"type": "drag", "lane": "from_pitch_delta"}
    },
    {
      "name": "gliss-to-slide",
      "match": {"articulations": ["gliss"], "duration_min": 0.15},
      "emit": {"type": "slide", "path": "pitch_to_x"}
    }
  ],
  "defaults": {
    "tap_lane": "from_pitch_delta",
    "unmatched": "drop"
  }
}
```

### 3.2 匹配与生成模型
- **自上而下第一条命中生效**（顺序 = 优先级，默认规则兜底）。**技法规则优先于音高细则**：如 `drums-roll`（tremolo）必须排在具体鼓件规则之前，否则带滚奏记号的军鼓永远被 `drums-snare` 截胡。
- `match` 条件：字段相等（`instrument`/`pitch`/`tied`）、集合包含（`articulations` ∈、`pitch_in` ∈）、范围（`duration_min/max`、`duration_beats_min/max`）、上下文（`next_interval_beats_max` = 与**同乐器相邻事件**的最小间隔拍数，首事件看后向、末事件看前向、中间取前后最小——密集度与方向无关）、存在性（`"pitch": null`）。`"param:x"` 字符串先经 params 解析。
- `emit` 值三类：**固定值**（`"lane": 2`）、**来源引用**（`"lane": "from_pitch"` = 音高→轨道连续映射（绝对，仅鼓件等固定音高映射场景）；`"lane": "from_pitch_delta"` = 相对音高轨道（旋律乐器默认，见 §3.4）；`"direction": "from_pitch"` = 参照 `pitch_end` 相对上下，上行→up 下行→down）、**生成器**（`"path": "pitch_to_x"` = 起点相对列→终点按 `pitch_end` 相对方向 ±1 列生成 slide 路径；`"path": "bend_offset"/"bend_offset_neg"` = 起 x → x±半音×0.5 轨；`"lane": "cross_lane"` = 扫弦 drag 序列，沿 `strum_pitches` 在 `strum_span_seconds`（默认 0.08s）内线性分布，多音按琴弦顺序绝对映射，单音用相对轨道）。
- **slide 输出必带 `lane` 起始轨**（`round(path[0].x)`，协议 §1.1 可选字段），供渲染对齐与 overlap 判定。
- 每歌曲一个规则文件（`chart_tools/rules/<song>.json`），可指定继承全局默认（`chart_tools/rules/default.json`），params 深合并（嵌套 dict 按键覆盖）。

### 3.3 记谱 → 音符语义映射表（2026-08-18 用户逐轮确认，权威版）

> 逐行确认过程与变更底稿见 `docs/音符对照表.md`；默认规则文件 `chart_tools/rules/default.json`。

**通用约定**
- 旋律乐器轨道 = **相对音高**（用户拍板 2026-08-18）：不用实际音高作谱，每个音符的列 = 前一音符的列 ± 方向——音高升右移 1 列、降左移 1 列、同音不动，超界钳制；旋律线首音符锚定中间列（`params.rel_start_lane`，默认 2）。鼓保持固定音高→固定轨道（底鼓 0→吊镲 3）。
- flick 方向语义 = 技法状态：上行（击弦/推弦/开镲）→ `up`；下行（勾弦/放弦/踏板镲/闷音/slap）→ `down`。
- **hold 阈值以拍数计（与 BPM 无关）：全乐器统一二分音符（2 拍）以内 → tap、二分及以上 → hold**；tie 链合并后计拍。
- slide：滑音/滑弦/gliss，duration ≥ 0.15s，path = 音高→x 线性映射。**推弦/放弦亦生成 slide：x 位移 = 半音数 × 0.5 轨（全音 = 1 整轨），推弦右移、放弦左移，不受 0.15s 下限约束。**
- drag：节奏不精确的重复技法（震音/滚奏/颤音/扫弦/密集幽灵音），Phigros 宽松判定。
- **同刻多音一律压缩 ≤2 轨（双轨上限，chord_split）。**
- 未命中任何规则 → tap（相对音高→轨道）。

| 军鼓 37/38/40 | tap | 1 | — |
| 嗵鼓 41/43/45/47/48/50 | tap | 3（绿键重映射；忠实模式回 2） | — |
| 闭镲 42 | tap | 2 | — |
| 开镲 46 | flick | 2 | up |
| 部分闭镲/踏板镲 44 | flick | 2 | down |
| 吊镲/叮叮 49/51/52/55/57/59 | tap | 3 | — |
| 滚奏/震音 | drag | 2 或 3 | — |

**跨乐器通用规则**

| 来源 | 处理 |
|---|---|
| BPM 变化 | events.bpm（前端换算时间按段积分） |
| 拍号变化 | 仅影响网格换算，不生成音符 |
| 同刻多音 | 一律压缩 ≤2 轨（chord_split；slide 不参与翻位——连续坐标音符由 path 定位） |
| 超密段（>8 音/秒） | 转换报告警告，不静默删音 |
| 同轨长音重叠 | 先开始者截断到后者开始（slide 截断时 path 末点同步线性插值）；**后者为 hold 才降级 tap，slide 保持**——pad 持续音上推弦属正常编曲，不丢 slide 路径 |
| 力度/重音 accent | 不参与类型映射，保留字段供未来修饰 |

### 3.4 音高 → 轨道 / x 坐标映射
- 鼓：2.3 表直接给 lane（底鼓 0、军鼓 1、HH 家族 2、吊镲类 3）。
- 旋律乐器 = **相对音高轨道**（`from_pitch_delta`，用户拍板 2026-08-18）：同一乐器旋律线按 tick 排序，`lane[i] = clamp(lane[i-1] + sign(pitch[i] - pitch[i-1]), 0, 4)`；同音高/无音高事件保持当前列；首音符锚定 `rel_start_lane`（默认中间列 2）。**只编码旋律走向，不编码音程大小**；同向密集段（琶音等）会累计到边缘列饱和钳制——属预期行为，可通过 `rel_start_lane` 或未来加"饱和回弹"策略调节。
- slide 的 path 起点 x = 相对轨道（规则声明 `"lane": "from_pitch_delta"` 时），终点按 `pitch_end` 相对起点音高的方向 ±1 列；推弦/放弦保留半音×0.5 轨位移公式，仅起点锚定相对化。

## 4. 冲突解决与边界案例（规则引擎必须处理）

| 案例 | 处理 |
|---|---|
| 同刻同轨多音（和弦超限） | chord_split 逻辑：翻相邻空位，无空位则保留碰撞（谱面质量警告）；slide 不参与翻位 |
| 同轨长音重叠 | 先开始者截断到后者开始（slide 截断 path 末点插值）；后者为 hold 降级 tap，slide 保持（规则 `overlap` 组配置） |
| 超密段（> N 音/秒，默认 N=8） | 输出警告列表（不静默删音）；规则可选降采样 |
| grace → flick 的时机 | flick 生成在主音 time 上，时长窗默认 ±10ms（可配） |
| slide 路径起点≠整数轨 | 允许小数 x 起点（连续坐标），起始 lane 取最近整数轨供渲染对齐 |
| pitch=null 事件（打击噪声） | 规则匹配 `{"pitch": null}` 显式处理，未命中走 `unmatched` |

## 5. 验证与回归

1. **确定性**：同输入两次运行输出逐字节一致（禁止随机/时间戳进入输出）。已实现于 `rule_engine.py`（纯函数 apply），CLI 已实测。
2. **往返**：已有谱面 → 反推 IR → 重生成，音符集一致（沿用 chart↔MusicXML 零差异方法论）。待 .chart/mscz 前端接入后实施。
3. **校验断言**（转换器内置）：音符数守恒（规则未丢弃时）、无负时长、lane ∈ 0-4、slide path t 单调且首 0 末 duration、x ∈ [0,4]。已实现（`_validate`），失败记警告不中断。
4. **警告清单**：所有降级/冲突/丢弃项必须出现在转换报告（⚠ 标记），延续转录谱对照表惯例——**AI 产出不可盲信，警告比谱面更值钱**。已实现。
5. **单元测试**：`chart_tools/test_rule_engine.py`（33 例，unittest 无依赖）：default.json 全规则路径、post 处理、校验、确定性、IR 往返。`python -m unittest test_rule_engine`。

## 6. 版本与扩展策略

- `formatVersion` 字段管理兼容：游戏加载侧按版本分派解析。
- **加音符类型**：只加 `type` 值 + 字段，旧谱面不破坏（增量）。
- **加事件**：只加 `events[].type`，同理增量。
- **规则语法演进**：`rules` 文件带 `version`；旧版本文件由引擎自动升级或报错。
- **不做**：chart→乐谱的保真逆转换（信息损失，不承诺）。
