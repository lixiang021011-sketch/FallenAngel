## 0. 查到的实际做法（集成战略，出处见 §8）

| 问题 | 集成战略的实际做法 | 对我们这一稿的影响 |
| --- | --- | --- |
| 进入下一层怎么表现 | **一屏「时刻 + 层名 + 一段氛围引言」**，不是加载进度条。例：第 1 层 `17:03` / *Mist-stricken Missteps*（云雾迷途）+ 三行文字；第 5 层 `00:00` / *Blood-soaked Corridor*（血染的走廊）；第 6 层时刻直接写成 `--:--`（时间已经不存在）。每层另配一段**该层专属的失败文案**；结算里会记一条 `You entered the {层名} zone`。 | 我原先主推的"细进度线"是错的：**过渡的主体是「时刻 + 层名 + 一段话」**，进度条只在真加载慢时兜底。 |
| 层的结构 | 每层节点数**固定**（前五层 4 / 4 / 6 / 6 / 7，第六层固定 4 个），并且**层末必有一个固定节点**（第 1 层末＝行商、第 2 层末＝馈赠、第 3 层末＝强敌、第 4 层末＝馈赠、第 5 层末＝强敌）。分支只发生在层内。 | "每步 2 个候选"的方向是对的；但**层末应当钉一个固定节点**——我们第 1 层末正好是商店（对应行商 ✓），第 2 层末现在是硬仗（✗，按参照应改成"馈赠"）。 |
| "信息细节度不同"怎么做的 | **不是按层递减**，而是**节点级遮蔽**：个别节点被标成**「浓雾（Dense Fog）」**，在它变成可达之前**完全无法辨识**，只给一句"雾里有什么东西，但你看不清"；可达时揭开。此外还有**上锁的分支**（看得见、进不去）与**隐藏的分支**（条件不满足时看不见）。 | 我原来写的"越远的行越模糊"是**我编的**，参照里没有。真实做法是"整层可见 + 少数节点被雾遮住"。两者可以并存，但必须分开写清（见 §5）。 |
| 能不能改路线 | 自阴云火花起可以**花代价改路**：花 1 把钥匙／1 点干扰指数，跳到当前分支里的任意另一个节点，连路线一起改。 | 我提的"付费捷径"有了真实对应物：**不是入场路费，而是花东西换路**（见 chapter-route-spec 的待拍板）。 |

## 1. 什么时候出现过渡

| 时机 | 出不出现 | 备注 |
| --- | --- | --- |
| 同一层里换站（第 5 站 → 第 6 站） | ❌ 不出现 | 只在跨层时出现，否则一局要被打断十几次 |
| **从第 N 层进入第 N+1 层** | ✅ 出现一次（「时刻 + 层名 + 一段话」那一屏） | 一局最多两次（1→2、2→3） |
| 进终房 | ✅ 用同一套，但文案换成"这一程的落点" | 与结算页衔接 |
| 退出/放弃本局 | ❌ | 走现有的确认弹窗 |

**三条硬性要求**（写进实现约束）：

1. **一屏、等玩家确认**：像集成战略那样停在那屏上等按键（任意键／点击继续），**不是限时动画**；
   想多看两眼就多看两眼。
2. **不阻塞加载**：下一层的地图数据、商店候选、谱面在后台准备；**只有真加载慢**时才在底部补一条细进度线，
   平时的过渡里没有进度条。
3. **同层不出现**：只在跨层与进终房时出现，一局最多三次。

## 2. 过渡的三个候选

| # | 做法 | 好处 | 代价 | 建议 |
| --- | --- | --- | --- | --- |
| ① | **时刻 + 层名 + 一段氛围引言**（集成战略的真实做法） | 一屏就把"换了一层世界"交代完；层名与时刻本身就是叙事 | 每层要写 3–4 行文案 | **主推（照参照）** |
| ② | 黑场 + 层名淡入（一行小字） | 省；深色里只有字 | 信息量为零，像加载而不是换层 | 备选（文案没写好时用它） |
| ③ | 地图不动，只推近 + 层名浮出 | 不打断视线 | 存在感弱，容易被误认为卡顿 | 备选 |

**第一章的三层文案草案**（照参照的"时刻"写法：时间越走越晚，第三层已经不是正常时间）：

| 层 | 时刻 | 层名（草案） | 引言（草案） |
| --- | --- | --- | --- |
| 第 1 层 | `17:03` | 放学路上的风 | 天还没黑。你戴上耳机，路还是你认识的那条路。 |
| 第 2 层 | `20:36` | 灯亮起来的地方 | 商场早就关门了，可中庭的灯还亮着。没有人，但有人来过。 |
| 第 3 层 | `00:00` | 不是时间的那个点 | 末班车早开走了。你还在走，路已经不像刚才那条了。 |
| 终房 | `--:--` | 这一程的落点 | 到这里，钟不走了。（沿用参照"时间不存在"的写法） |

每层再各写一句**失败文案**（参照里每层都有）：本局在这一层失败时显示。

## 3. 自身状态栏

字段与来源（全部来自局内快照 `PortfolioGrowthRunData`，不新建一套账）：

| 字段 | 来源 | 第 1 层 | 第 2 层 | 第 3 层 |
| --- | --- | --- | --- | --- |
| 现金 | `runCash` | ✅ 全 | ✅ 全 | ✅ 全 |
| 层与步 | `layer` / 当前站序号 | ✅ | ✅ | ✅（**深层唯一的位置信息**） |
| 负面状态 | 每层一个（设计稿 §5.3，未接线） | ✅ 名称 | ✅ 名称 | ✅ 名称 |
| 人情 | 升级发放（设计稿 §3.4，未接线） | ✅ 数值 | ✅ 数值 | ➖ 收进册子 |
| 局内等级 | 经验（设计稿 §3.5，未接线） | ✅ 带进度条 | ✅ 只给数字 | ➖ 收进册子 |
| 旅伴 | 本层同行（设计稿 §3.6，未接线） | ✅ 名字 + "本层" | ✅ 名字 | ➖ 收进册子 |
| 生命值 | **不放状态栏** | 逐曲重置，属于演奏页 HUD | | |

## 4. 装备栏

- **8 格**（设计稿 §5.2），一局内不变；满格时拿到新件要**置换或卖掉**（卖出规则仍待拍板）。
- 稀有度沿用价格表：**白 40 / 蓝 80 / 金 160** → 描边颜色按稀有度走（白/蓝/金）。
- **一次性件**（如"备用弦""备用的那把"）用掉后打一个红点，不消失——它是记忆的一部分。
- 点任一格 → **详情卡**：名字 + 一句话 + 来历（设计稿 §4.2 的三种来历） + "白 · 40 · 第 1 层买到"。

| 层 | 装备栏显示 |
| --- | --- |
| 第 1 层 | 格子 + 稀有度描边 + 编号；点开看名字与来历 |
| 第 2 层 | 格子 + 稀有度描边（名字只在详情卡里） |
| 第 3 层 | 统一灰、连稀有度也不显示（东西还是你的，但你不再数它们） |

> 第 3 层那一档在效果图里标了**反例警告**：它会削弱"刚买到好东西"的爽感。若作者觉得太狠，
> 退一档——保留稀有度描边，只把名字收起来。

## 5. 每层信息细节度（总表）

**先说清两条不同的东西**：

- **参照的做法（节点级浓雾）**：整层的节点与连线都看得见，但**个别节点被"浓雾"遮住**——
  在它变成可达之前连类型都不给，只给一句"雾里有什么东西，但你看不清"；可达时揭开。
  另有"上锁分支"（看得见、进不去）与"隐藏分支"（条件不满足时看不见）——**信息与通行权分开**。
- **我们要加的那一层（按层递减）**：这是**作者口径**（"不同层级信息细节度不同"），参照里没有。
  它管的是**界面信息量**（状态栏/装备栏/地图各自显示多少），与上面的"节点遮蔽"是两件事，可以并存。

### 5.1 界面信息量（我们的加法）

| 界面 | 第 1 层（近） | 第 2 层 | 第 3 层（远） |
| --- | --- | --- | --- |
| 过渡 | 时刻 + 层名 + 引言 | 同左 | 同左（时刻写成 `00:00`，已经不是正常时间） |
| 状态栏 | 全字段 | 收起来历与进度条 | 只剩 现金 / 层与步 / 负面 |
| 装备栏 | 描边 + 名字 | 只有描边 | 统一灰 |

理由：与基调一致（"越远越离开现实"），也让**情报类道具**（抄歌本＝本层可见、司机＝下一层可见）
在深层更值钱——信息本身就是这一程的货币之一。

### 5.2 地图可见性（照参照改）

| 看什么 | 做法 |
| --- | --- |
| 本层地图 | **整层可见**（节点 + 连线），玩家一眼能规划路线 |
| 下一步的候选 | 类型可见（演奏 / 硬仗 / 商店 / 事件 / 休息）——这一条现在代码里已经实现 |
| **被"雾"遮住的节点** | 类型也不给，显示"雾"与一句氛围文字；**变成可达时揭开**（照参照的 Dense Fog） |
| 更深的层 | 看不见（一层一层地展开，不显示未来两层的缩略） |
| 情报类道具 | 抄歌本＝揭开本层剩余节点；司机＝揭开下一层；与"上锁/隐藏分支"配合使用 |

> 这一条**推翻**我上一稿的"更远的行显示 ？"：那不是参照的做法。参照是"整层可见，少数节点被雾遮住"，
> 而"锁定 / 隐藏分支"把**通行权**与**可见性**分开处理。代码里现存的"远处显示 ？"要按这条改掉。

## 6. 待拍板

1. **过渡改版**：按参照用「时刻 + 层名 + 引言」（主推）；三层文案草案在 §2，需要你过稿或重写。
   以及"继续"的触发键（任意键 / 只认点击）。
2. **信息模型二选一**：(a) 只照参照做"节点级浓雾 + 上锁/隐藏分支"，**不做**按层递减；
   (b) 两者都做（浓雾 + 按层递减，本稿的样子）。我倾向 (b)：参照管"路上看得见什么"，
   递减管"你自己身上的东西显示多少"，两者不冲突。
3. **第 3 层装备栏**：统一灰（本稿）还是保留稀有度描边。
4. **状态栏位置**：地图页顶部（本稿），还是常驻在所有成长页（商店/装备/册子）。
5. **详情卡要不要显示"来历"**：它是"曾经有人为它花过时间"的唯一出口（设计稿 §2.5），
   建议保留，但作者可以决定它只出现在册子里。
