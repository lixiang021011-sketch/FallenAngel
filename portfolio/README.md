本目录是作品集的**内容源**：文案、结构与打包清单。素材（截图/录屏）由本人补充，位置见每节末尾的【待补素材】。

## 一、项目概览

**FallenAngel** — 竖屏下落式音游 + roguelike 行程与永久成长的单人 Demo。

- 平台：Android（竖屏 1080×1920 基准，适配到 20:9）/ Windows 可运行包
- 引擎：Unity 2022.3.62f3c1（C# 9）
- 规模：`Assets/Scripts` 约 50 个脚本、10 个页面与状态、两套配置表体系（成长 / 行程）
- 我的角色：玩法设计 + 全部程序实现 + 程序化美术管线 + 数值模拟与验证工具

一句话卖点：**把"打歌"包进一局 roguelike 行程——每局是一次出海，路上做选择，局终把成果沉淀成永久成长。**

## 二、玩法与系统拆解

### 2.1 双层循环

| 层 | 内容 | 时长量级 |
| --- | --- | --- |
| 局内（一次行程） | 起点 → 房间（战斗/商店/空房）→ 终点；分叉必有一条免费出口，付费路线用局内现金换更高收益；三次演奏累积积分 | 5–8 分钟 |
| 局外（永久成长） | 24 节点 + 3 处交汇的天赋树（满树 3600 分）：收益保底、利息、商店刷新、路费减免、可选折扣 | 长期 |

### 2.2 收益引擎（整曲结算级）

按固定顺序结算，保证可预测：**原始奖励 → 增幅按来源加算 → 保底补足 → 封顶 B×1.5**；利息独立成一条，不进增幅/保底/封顶。

已接线效果：I0/I1 整曲 Perfect 双线达标、J0/J1 付费挑战奖励、D0 演奏增幅、E05 无 Miss 增幅、G0/G1 收益保底、C1 开曲利息；K1/E08 是"每局有限次主动使用"，勾选才生效，且不优于常驻折扣时不消耗次数。

### 2.3 关键取舍

- 效果优先"语义完整 + 零新基础设施"：乐句级效果（A/B/C/K0）标注"待乐句统计接入"；商店里未接线的装备在 UI 上明示，不让玩家当结算 bug。
- 路线分叉保证"永远有免费出口"，避免 roguelike 随机把玩家卡死在买不起的付费路上。

【待补素材】行程地图全景、商店固定详情区、天赋树、结算明细。

## 三、技术实现与亮点

### 3.1 分层与约束

`Core`（状态机/会话/存档事务）+ `Data`（只读配置表）+ `UI`（页面与组件）+ `Gameplay`（音符/判定）+ `Audio`。约定：时间一律取 `GameManager.SongTime`；音符只经 `NoteSpawner` 对象池创建；行程状态机走 `PortfolioSession`，不复活已删除的旧 RunManager。

### 3.2 事务性存档（最值得讲的一块）

积分消耗、购买、解锁、开曲与结算都按"**先落盘、再确认**"处理：

- 修订号 + 校验和：磁盘版本落后不能覆盖新状态；被截断但语法合法的 JSON 不会被当成新档；
- 写失败无副作用：不扣钱、不给奖励、不标记成功，可重试；
- 旧版本备份保留，显式恢复才回滚；
- 演出中断（强杀）按失败结算，未完成曲目不给分。

### 3.3 验证体系（可无头运行）

- **95 项**编辑器确定性校验：配置表一致性、天赋前置与排他、存档事务、地图与掉落、折扣与利息叠加；
- **27 项**图标几何自检：按真实宿主尺寸重建网格，量墨迹包围盒中心与是否溢出（本轮正是靠它抓出"图标零件整体偏半格"的根因）；
- 两者都能 `-batchmode -executeMethod` 运行，提交前自证，不靠肉眼。

### 3.4 程序化美术管线

图标/按钮/卡片/房间符号由**同一份几何定义**同时产出：游戏内网格（`DeepSeaGraphic`，单色可着色、任意尺寸清晰、不占贴图内存）与交付件（`art_tools/source/*.svg` + `Assets/Art/ui/*.png`）。改一处两边同步，40 件美术交付件与 16 类组件由此产出。

【待补素材】程序化图标总览（可直接用 `art_tools/review/sheet_icons_and_marks.png`）、四方向选型对比（`art_tools/review/directions/directions_compare.png`）。

### 3.5 数值不是拍的

`balance_sim.py` 按引擎同语义跑 15 局 × 5 种子 × 3 档水平，暴露四个结构问题：成长节奏与水平无关、I0 阈值一票否决、付费路线净增益仅 +6.4、80 元装备永远买不起。据此把 I0 改成上下双线达标、路费 60→40、E05 价格 80→60，重跑确认收益梯度恢复（新手 113 / 普通 116 / 高手 146）。

## 四、经验与教训

1. **先量化再动手**：图标"看着有点偏"排查了三轮，最后靠几何自检量出墨迹尺寸，才定位到偏移函数把"相对中心"当成了"绝对坐标"。
2. **字段语义不要复用**：同一个 `variant` 既表示节点类别又当圆角半径，悄悄破坏了所有天赋节点。
3. **早给验收工具留边界**：临时验收悬浮条集中在一段 `#if UNITY_EDITOR` 里，打包前一删即净。
4. **两份美术会漂移**：导出器与游戏内几何必须同源，否则手改一边就永久分叉。

## 五、演示脚本（录屏/截图用）

建议 30–60s 一局完整循环，按下列顺序拍：

1. 主菜单（3s）→ 选择存档（2s）
2. 行程地图：拖动、点选房间、付费路线抽屉（8s）
3. 商店：选商品 → 详情 → 购买 → 余额与候选变化（8s）
4. 演奏：命中反馈、底鼓全宽、长按（10s）
5. 结算：收益明细逐项 + 评级（8s）
6. 天赋：解锁一个节点（消费确认）（6s）
7. 回到地图看到装备/现金变化（4s）
